# Miku Writing Style OS v1.1｜長文改行ルール差分

> Status: Current / Canonical Delta / Operational  
> Version: v1.1 Delta  
> Effective date: 2026-09-02  
> Base source: `06_Writing_Style_OS/WRITING_STYLE_OS.md` v1.0  
> Scope: note記事、Session Archive、Story、Practice、教材説明文その他の公開・準公開長文、およびHuman向け長文出力

## 1. 目的

v1.0の会話ログ分析にある「一文で終わる発言が多い」「短い応答でテンポを保つ」という特徴を、公開長文の段落設計へ誤適用しないための運用差分。

みくらしい長文の勢いは、短文を一文ずつ改行して作るものではない。口語接続、思考の連鎖、ツッコミ、理解の切り替わり、感情の動きを一つのまとまりとして走らせることで作る。

本差分がv1.0の一般記述と競合する場合、対象範囲については本差分を優先する。

## 2. 長文段落ルール

- 会話ログにおける「一文で終わる発言」の統計を、公開文章の「一文一段落」へ変換してはならない。
- 原則として、一文ごとの機械的改行を行わない。
- 同一の出来事、論点、感情の流れ、ツッコミとその説明が連続している間は、自然な一つの段落として保持する。
- 勢いは改行数ではなく、`だってさぁ`、`いや`、`ほんで`、`でもこれがさ`、`そもそも`、`ということは` 等の自然な口語接続と、思考が次へ転がる流れで作る。
- 短い単独段落は、パンチライン、強いツッコミ、場面転換、理解が切り替わる瞬間、意図的な余韻など、単独化する意味が明確な場合に限る。
- 視認性のためだけに文章を細切れにしない。スマートフォンでの可読性を「改行を増やすこと」と同一視しない。
- 長文では、読者が会話を横で聞いているような連続性を優先する。整いすぎた説明文にも、短文カードを縦に積むような文章にも寄せない。

## 3. Session Archive追加ルール

Session Archiveの「生ログ感」「ライブ感」「勢い」を、短文＋大量改行で演出してはならない。

Archiveでは、Primary Evidenceとしての実際の発言・出来事を保持しながら、その前後を長めの自然な口語段落でつなぐ。`だってさぁ`、`いや`、`ほんで`、`でもこれがさ` 等の接続によって、当時の混乱、ツッコミ、理解、次の事件が一続きに進む感覚を作る。

実際の短い発言を引用する場合でも、その引用が短いという理由だけで前後の地の文まで細切れにしない。Evidenceの忠実性と公開文章の段落設計は別問題として扱う。

## 4. Pre-Human Review Style QA Gate

長文をHuman Reviewへ提出する前に、制作AI／監査AIは以下を確認する。

1. 一文だけの段落が連続していないか。
2. 改行の主目的が「なんとなく読みやすそう」「Web文章っぽい」になっていないか。
3. 同じ出来事・論点・感情の流れを、不必要に複数段落へ分断していないか。
4. 会話ログの短文率を、公開長文のレイアウトへ誤適用していないか。
5. Session Archiveの場合、生ログ感を短文改行ではなく、口語接続と長い思考の流れで作れているか。

違反がある場合はHuman Reviewへ進めず、意味・Evidence・事実関係を変えずに段落構造を修正してから再確認する。

## 5. 適用上の注意

本ルールは「長い段落ほど良い」という規則ではない。段落は意味単位で切る。必要な改行は残す。

また、Practiceの手順、チェックリスト、法務・安全上の注意、操作説明など、構造化そのものが理解や実行性を高める箇所では、成果物の目的を優先する。ただし、その場合も説明文を一文ごとに機械的に分断しない。

## 6. 今回の再発防止Evidence

2026-09-02、S1-2 Session ArchiveのHuman Review Candidateにおいて、v1.0の会話ログ由来の短文特徴および一般的なWeb文章の可読性パターンが、公開長文の段落設計へ過剰適用された。Human Reviewで「文字で見ると改行が多い。もっと勢いを」と指摘され、既存Writing Style OSを確認した結果、Source未参照ではなくSource適用解釈の誤りと判定した。

このため、再発防止を注意喚起ではなく、長文用の解釈ルールとPre-Human Review QA Gateとして正式化する。
