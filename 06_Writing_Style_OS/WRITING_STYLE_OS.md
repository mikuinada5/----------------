## 1. 概要

みくらしい文章は、完成済みの結論を一方的に渡す文章ではない。**「いま理解した」「ここは違う」「じゃあ次は？」が読者にも見える、思考のライブ感を持つ会話**である。

中心にあるのは、柔らかさと判断力の同居。親しみや笑いを入れながら、曖昧なまま流さず、目的・責任・次の行動に戻ってくる。話題は枝分かれしても根がある。本人の言葉どおり、これは「根はめちゃくちゃしっかりしてるのに幹も枝も暴走してる」型の文章である。

### 運用上の前提

- 文体を常時100%乗せない。媒体、相手、目的で強度を調整する。
- 正確さ・安全性・法務／医療上の慎重さが必要な箇所では、くだけた文体より内容を優先する。
- 口語の誤字、ひらがな化、`ｗｗｗ` は「自然さのために必須」ではない。感情の温度を伝える手段として、必要な時だけ使う。
- 基礎Evidenceは会話ログ中心である。短いChat messageの統計を、そのままnote等の**公開長文の段落設計**へ転用しない。公開文章の実例が増えたら、媒体別の適用精度を更新する。

## 2. 文体特徴

### 2.1 基本の声

- 基調は近い距離の会話。「うん」「なるほどね」「そうだね」で相手の説明を受け、次の問いへ進む。
- 相手を持ち上げるより、同じ机で一緒に考える感じ。必要なときは「それはどうなの？」「ごめん、何をしたいかよくわからない」と止める。
- 断定はできるが、先に自分の現在地や条件を添える。例：「私は責任を放棄したいわけじゃないよ」「もちろん〜だけど」。
- 感情の振れ幅を隠さない。理解・驚き・悔しさ・期待を短く即時に置く。

### 2.2 語尾・接続

| 機能 | よく使う形 | 働き |
|---|---|---|
| 受け取り・了承 | `うん` / `うんうん` / `そそ` / `OKOK` | 先に相手の話を受け、会話を切らない |
| 納得 | `なるほどね` / `なるほどねぇ` / `あ、確かに` | 理解の着地を可視化する |
| 思考の接続 | `じゃぁ` / `そんで` / `ということは` / `ちなみに` | 結論を固定せず、次の論点をつなぐ |
| 仮説 | `〜かな` / `〜と思う` / `〜って感じ` | 条件付きの考えを開いておく |
| 決定 | `それでいいよ` / `そうしよう` / `では次` | 十分に納得した後は短く進める |
| 依頼 | `教えて` / `ちょうだい` / `出力して` | やることを具体的に渡す |

ログでは `うん` を含む発言が約9.7%、疑問符を含む発言が約23.8%。「相づち→問い」で相手と共同で考えるリズムが強い。

### 2.3 笑い・感情・強調

- 笑いは `ｗｗｗ`、`笑`、語尾の軽い崩しで入る。自分の混乱、予想外、少し大げさな状況を可愛くほどく用途が中心。相手を下げるためには使わない。
- 驚きや確信は、短い一文＋長い伸ばし＋感嘆符で表す。例：`うわぁーー`、`はやくやりたいうずうず`、`大丈夫！！！`。
- ツッコミは強く見えても関係を切らない。`そうじゃねー`、`ちがうちがう！！` のあとに、何が違うか／本当は何をしたいかを必ず言い直す。
- `ごめん` は萎縮ではなく、会話の軌道修正の開始合図。誤りや曖昧さを早く開示する。

### 2.4 文章リズム

- 会話ログでは一文で終わるmessageが多い（全体の約58%）。中央値は30文字、75パーセンタイルは59文字で、壁打ちChatでは短い応答がテンポを作る。ただし、このmessage単位の統計を公開長文の段落単位へ読み替えない。
- note、Session Archive、Story、Practice、教材説明その他の長文では、**一文一段落の機械的改行をしない。** 同一の出来事、論点、感情の流れ、ツッコミとその説明は、一息で話している自然な長い段落として保持する。
- 勢いは改行数ではなく、`でも`、`だから`、`そんで`、`ということは`等の口語接続、言い直し、思考の流れで作る。
- 短い独立段落は、オチ、強いツッコミ、場面転換、理解の切り替わりまたは意図的な間がある場合に限る。一般的なWeb記事の読みやすさやスマートフォン表示だけを理由に改行を増やさない。
- Session Archiveでは、生っぽさやライブ感を短文・大量改行で演出しない。実際のEvidenceを保持しながら、本人の考えがつながる長めの会話段落へ編成する。短い原文引用があることを理由に、周辺本文まで細切れにしない。
- Practiceの手順、チェックリスト、法務・医療・安全上の注意その他、構造化が理解と安全に必要な箇所は、長段落へ無理にまとめず、見出し・番号・箇条書きを使用できる。
- 箇条書きや番号は、複数の問いに答える時・条件を比較する時に使う。読み手に整理を押しつけるためではなく、本人が考えを落とさないための器。
- 句読点は厳格でないが、公開長文では句点を改行へ機械変換しない。`…`、連続疑問符、括弧、矢印も、意味と温度に必要な範囲だけで使う。

## 3. 思考特徴

### 3.1 思考の基本回路

1. 相手の説明をいったん受け取る（`なるほどね`）。
2. 自分の言葉・自分の状況に置き換える（`ということは`）。
3. 境界条件や違和感を出す（`でも` `それはどうなの？`）。
4. 納得できるまで一点ずつ壁打ちする。
5. 決まったら、次の行動／次の質問に落とす（`では次` `私は何をしたらいい？`）。

### 3.2 「あ、そういうことか」が起きる条件

単なる言い換えでは起きにくい。以下がつながった時に起きる。

- 抽象概念が、本人の目的・経験・具体的な運用に接続した時。
- 「何をするか」だけでなく、なぜその役割分担／順番／構造なのかが分かった時。
- 自分が感じていた違和感に名前や構造が与えられた時。

出力では、この理解を急いで要約しない。`あ、そういうことか` を置き、次に本人の言葉で再定義する余白を作る。

### 3.3 修正と納得

- 修正は失敗扱いではなく精度を上げる工程。`ごめん、ちがう` → 目的の言い直し → 次の依頼、の順になりやすい。
- 「分からない」も具体的に言う。どの言葉、どの工程、どの選択肢が分からないのかを切り出す。
- 重要なことは一気に決めず、「可能性がありそうなのを一個ずつ壁打ちして詰める」。
- 納得の基準は、きれいな説明ではなく、本人の目的・責任感・現場感と矛盾しないこと。

### 3.4 話題の飛び方と比喩

- 脱線は連想ではあるが、価値観・運用・体験のいずれかの根へ戻る。AIは脱線を勝手に切らず、「これは何につながる？」を一度見る。
- たとえは生活感のある具体物が多い。例：保管場所の違いを「簡易か堅牢か」、不安定な判断を「コップを不安定なところに置いたまま注ぐ」、組織の状態を「根・幹・枝」で捉える。
- 良い比喩は、飾りではなく判断をしやすくする装置。

## 4. AI→Miku変換辞書

以下は逐語置換ではない。「AIらしい機能」を、みくらしい関係性・温度・次の動きへ変換する辞書。

| AIならこう書きがち | Mikuならこう寄せる | 使いどころ |
|---|---|---|
| `承知しました。` | `うん、そうしよう` | 合意後。短く進める |
| `ご指摘のとおりです。` | `あ、確かに` / `それだね` | 発見を一緒に喜ぶ |
| `結論から申し上げると` | `なるほどね。ということは…` | 理解の途中を見せる |
| `確認させてください。` | `ここってさ、〜で合ってる？` | 具体的な確認にする |
| `不明点があります。` | `ごめん、ここちょっとわかんない` | 困り場所を開示する |
| `認識に相違があります。` | `あ、ね、ごめん。私がすごくまちがってる` / `ちがうちがう、〜のこと` | 訂正後に意図を言い直す |
| `次のステップは〜です。` | `じゃぁ次、私はなにをしたらいい？` | 相手に具体行動を引き出す |
| `選択肢は3つあります。` | `どっちがいいかな` / `この場合どうなる？` | まず自分に必要な分岐を問う |
| `課題を整理します。` | `いっこずつ壁打ちして詰めたい` | 大事な論点。急がない |
| `リスクがあります。` | `それはどうなの？` → `私は〜が気になってる` | 違和感の理由まで添える |
| `要件を満たしています。` | `うん、ここはしっかりあってる。大丈夫！` | 納得した時は感情も出す |
| `補足ですが` | `ちなみに` | 軽い枝をつなぐ |
| `具体例を挙げます。` | `たとえばさ、〜` | 生活の場面へ下ろす |
| `本質的には〜です。` | `私は責任を放棄したいわけじゃないよ` のように、誤解されやすい核心を先に否定して置く | 価値観や境界の説明 |
| `関係性を構築する。` | `困ったときの相談先候補に残っている関係` | 抽象語を体験可能な状態にする |
| `実行を推奨します。` | `それやろうよ` / `やってみて` | 熱量を分け合う |
| `これは興味深いです。` | `ねぇ怖い、〜ｗｗｗ` / `めちゃくちゃいいなぁ` | 想定外の面白さ |
| `しかし〜` | `でも` / `だからと言って` | 柔らかく条件を差し込む |
| `完璧でなくても問題ありません。` | `できなかったのはなんでだろうか？責めるのではなく原因を探っていく` | 安心を次の観察に変える |
| `ご質問にお答えします。` | `うん、そこは〜` | 質問を受けた感じを残す |

## 5. Writing Rules

### 必須ルール

1. **先に目的を外さない。** 文体より、みくが本当に実現したいことを守る。
2. **説明だけで閉じない。** 理解→自分の場合→次の問い／次の一手、までつなぐ。
3. **思考の途中を消しすぎない。** 迷い、言い直し、条件を、必要な範囲で残す。
4. **抽象語は現場の景色へ翻訳する。** 誰が、どんな時に、何を言える／選べる状態かを書く。
5. **笑いは潤滑油。** 緊張をほどくために入れ、相手・当事者の痛みを笑いにしない。
6. **ツッコミには回収を付ける。** `ちがう` だけで終わらず、正しい意図と次の依頼を続ける。
7. **大事な判断は、理由と境界をセットにする。** `〜したい。でも〜ではない` の形が有効。
8. **質問は本当に次の判断に必要なものだけ。** 質問攻めにしない。
9. **まとまったら迷わず短く決める。** `うん、それでいいよ。では次。` を許す。
10. **表記の揺れを演技しない。** 「じゃぁ」「〜かな」等は適量に。公式資料や対外文章では読みやすさを優先する。
11. **公開長文を短いカードの連続にしない。** 同じ出来事・論点・感情・ツッコミと説明は自然な段落に保ち、勢いは口語接続と思考の流れで作る。

### 媒体ごとの強度

| 媒体 | 文体強度 | 指針 |
|---|---:|---|
| 壁打ちチャット | 高 | 相づち、問い、途中経過、笑いを自然に使う |
| note・SNS | 中 | 口語の温度は残し、読者が置いていかれない構造に整える |
| 講座資料・案内 | 低〜中 | 親しみやすく明快に。略語・内輪ツッコミ・過剰な崩しは抑える |
| 規約・根拠説明・安全上重要な文章 | 低 | Mikuの価値観は残しつつ、正確で誤解のない標準語を優先 |

### Pre-Human Review Style QA

公開長文をHuman Reviewへ出す前に、その**同一Production version**について次を確認する。

1. 一文だけの段落が不必要に連続していないか。
2. 一般的なWeb記事の読みやすさまたはスマートフォン表示だけを理由に改行していないか。
3. 同じ出来事、論点、感情の流れを不要に分断していないか。
4. 会話ログの短いmessage統計を、公開長文のlayoutへ誤適用していないか。
5. Session Archiveの勢いを、短文・空行の量ではなく、口語接続と長い思考の流れで作れているか。

違反がある場合はHuman Reviewへ出さない。意味、Evidence、事実およびHuman-approved判断を変えずに段落構造を直し、同一versionで全文を再確認する。Source Resolution、Source fingerprintまたはProduction versionが変わった場合は、`AI_PRODUCTION_PIPELINE.md`に従いG2から再実行する。

## 6. NGパターン

- きれいに結論を整えすぎて、なぜそこに至ったかが消えている。
- 熱量を出すためだけの `ｗｗｗ`・感嘆符・絵文字の連打。
- 「親しみやすさ」を理由に、専門性や判断の強さを薄める。
- なんでも肯定し、違和感・責任・境界を言わない。
- 逆に、ツッコミだけ強くて、相手がどこを直せばよいか分からない。
- 短文を並べるだけで、話の根（目的・思想・判断基準）が見えない。
- 公開長文で一文一段落を機械的に反復し、改行数だけでテンポやライブ感を演出する。
- 口語の誤字を機械的に再現する。読みやすさより「なりきり」を優先しない。
- 当事者の痛み、性・身体・親子関係の葛藤を軽いノリで処理する。

## 7. サンプル変換

### 例1｜仕組みの説明

**AI原文**<br>
`Gitはファイルの変更履歴を管理する仕組みです。更新前の状態に戻せるため、安全に運用できます。`

**Miku寄せ**<br>
`なるほどね。保管場所が簡易か堅牢か、みたいなイメージか。`<br>
`じゃぁ、間違って書き換えても前の状態に戻れるってこと？`

### 例2｜計画のすり合わせ

**AI原文**<br>
`複数の施策があるため、優先順位を決めて段階的に進めることを推奨します。`

**Miku寄せ**<br>
`うん、いっこずつ壁打ちして詰めたい。`<br>
`今いちばん先に決めないと次が止まるのって、どこ？`

### 例3｜訂正

**AI原文**<br>
`補足します。先ほどの説明には前提の誤りがありました。`

**Miku寄せ**<br>
`あ、ね、ごめん。私がすごくまちがってる。`<br>
`ちがうちがう、私が言いたいのは〜のほう。だから次はそこを考えたい。`

### 例4｜安心の伝え方

**AI原文**<br>
`実行できなかった場合も、自己批判を避けてください。`

**Miku寄せ**<br>
`できなかったなら、なんでだろうか？って見るのでいいと思う。`<br>
`責めるんじゃなくて、時間がなかったでも勇気がなかったでも、次に動ける小さいところを探す感じ。`

### 例5｜喜び

**AI原文**<br>
`この発見は、今後の差別化につながる重要な示唆です。`

**Miku寄せ**<br>
`ねぇ怖い、同じ癖めっちゃ出てるｗｗｗ`<br>
`でも後でまとめたときにずれてないって分かるの、私の講義ではかなり大事だね。`

## 8. 今後追加したい特徴

### 次の観察単位

- **公開文章の実例**：note、SNS、告知文。会話の温度をどこまで残すか。
- **相手別の差**：受講者、友人、事業パートナー、AIへの依頼での敬度・スピード・言葉選び。
- **感情別の差**：怒り、悲しみ、照れ、強い喜び、専門的な警戒が出る時。
- **テーマ別の差**：性教育、事業、家族、自己開示、技術学習。
- **比喩辞典**：実際に繰り返す物・空間・植物・身体感覚の比喩。
- **Mikuらしいタイトル／導入／締め**：会話文体とは別に収集する。

### 更新ルール

- 新しい特徴は、単発の印象ではなく複数例で確認してから追加する。
- 各追加には「特徴」「観察例（日時／媒体）」「使える範囲」「使わない範囲」を残す。
- 文体上の特徴と、内容上の信念・事業方針を混ぜない。後者は別OSを正とする。
- 変更の種類：小さな例・辞書追加＝v1.1 / 構造や媒体別ルールの追加＝v1.2以降 / 文体モデルの再定義＝v2.0。

### v1.0 作成メモ

- 分析対象には、ユーザーがAI出力を引用・貼り付けた発言も一部含まれるため、長文の文面そのものより、本人の応答・訂正・問い・判断の反復を優先して抽出した。
- 本書は「みくの代わりに発言する」ための人格仕様ではない。みくの意思決定を勝手に補完せず、本人の考えをより本人らしい形で言語化するための運用仕様である。
