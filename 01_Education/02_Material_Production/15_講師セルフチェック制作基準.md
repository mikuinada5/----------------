# 15_講師セルフチェック制作基準

## 1. 本基準の目的

本基準は、承認済み教育設計および関連する正式成果物に基づいて、講師セルフチェックを制作する際の共通基準を定める。

講師セルフチェックは、講師が講義実施後に、

- 承認済み教育の最低ラインを実施できたか
- 実施できなかった事項があるか
- 正式資料を確認しても判断できない事項があるか
- 今回の実施から何を次回へつなげるか
- 教材・資料側へ返すべき疑義やフィードバックがあるか

を自ら確認し、実施経験を次回の講義へ接続するための成果物である。

本成果物は、講師に点数・ランク・合否を付ける評価票ではない。

また、講師日誌、実施報告書、講師養成教材、能力開発計画、教材品質監査票、実施前チェックリストとして使用するものではない。


# 2. 上位基準・他成果物との位置づけ

本基準は、少なくとも以下の上位基準に従う。

- `00_教材制作システム概要・共通原則.md`
- `01_制作AI_判断・裁量基準.md`
- `02_教材制作・品質保証フロー.md`

15_講師セルフチェックは、10〜14その他の成果物別制作基準と同様に、承認済み教育設計を共通の正式Sourceとして、その成果物固有Missionに基づいて独立制作する。

15は、

- `13_講師進行表` を変換して作る成果物ではない
- `14_講師実施設計` を短縮・チェックリスト化して作る成果物ではない
- 13・14を代替する成果物ではない

13・14は、15の制作および実施時に、

- 同一の教育活動・Section・必須事項等が整合しているか
- 講師が何を実施責任として担っているか
- 必須教育内容・必須実施条件・裁量境界等がどのように定義されているか

を横断照合・参照する正式成果物として扱う。

15の正式なチェック責任は、承認済み教育設計・上位基準等へ遡って確認できなければならない。

13または14に記載されていることだけを理由として、制作AIが新しいチェック責任を生成してはならない。

一方、承認済み教育設計等から15で確認すべき正式な最低ラインが成立している場合、13・14側での記載欠落等を理由として15から省略してはならない。

資料間に矛盾・欠落・判断不能がある場合、制作AIが独自に整合させず、上位判断へ戻す。

本基準は、

- 教育設計
- 講師進行
- 講師実施設計
- 講師養成
- 講師評価
- 認定制度
- ライセンス制度
- 契約・運用制度

等を代替・新規定義するものではない。


# 3. 成果物固有Mission

講師セルフチェックのMissionは、

> **講師が今回の講義について、承認済み教育の最低ラインを実施できたかを事実として確認し、必要な内省・確認・共有を行い、その経験を次回の実施へつなげられる状態を支えること**

である。

セルフチェックは、

> **できたことを証明するための資料**

ではなく、

> **実際に何ができ、何ができず、何が判断できなかったかを正確に確認するための資料**

である。

教育実施としては、正式なチェック対象となる全項目が成立している状態を最低ラインとする。

ただし、セルフチェック行為そのものの目的は「全項目をできたにすること」ではない。

「できなかった」「判断に迷う」を正確に発見・記録できたことを、セルフチェックの失敗として扱わない。


# 4. 受講者ゴール・学習成果の扱い

15は、受講者の学習ゴールそのものを講師が達成判定する成果物ではない。

承認済み教育設計上のゴールは、

> **その教育活動によって受講者に何を成立させるか**

を示す。

15では、そのゴールをセルフチェック項目の教育的基準として参照する。

ただし、講師が判定する対象は、

> **そのゴールを成立させるために、講師自身が実施責任を持つ行為・条件を実施できたか**

とする。

以下のような受講者の内的状態・学習成果を、

- 理解した
- 腑に落ちた
- 気づいた
- 安心した
- 納得した
- 行動する気持ちになった
- 内省できた

等について、講師が「達成した／達成していない」と自己判定するチェック項目を原則作成しない。

また、

- 表情
- 発言
- 質問数
- 反応の大きさ
- 発表内容
- 場の雰囲気

等のみを根拠として、受講者ゴールの達成／未達成を判定してはならない。

受講者反応は、必要に応じて講師自身の内省材料となり得るが、学習成果そのものの達成判定とは区別する。


# 5. 15が担う責任

15は主として以下を担う。

1. 今回の講義実施の識別
2. Sectionごとの最低ライン実施確認
3. 講義全体に共通する最低ライン実施確認
4. 「できなかった」事項についての必要な内省
5. 「判断に迷う」事項の識別と正式な確認先への接続
6. 教材・資料への疑義・不具合等のフィードバック導線
7. 講義全体についての内省
8. 次回の実施へつなげるための記録

15は、今回の実施について確認・内省・共有するところまでを担う。

教育設計・教材・実施基準等の変更要否を判断する成果物ではない。


# 6. 15が担わない責任

15は以下を担わない。

- 講師に対する点数・ランク・合否・認定
- 講師能力そのものの評価
- 講師養成
- 学習・訓練・能力開発計画
- 講師育成の進捗管理
- 実施前準備チェック
- 教材そのものの制作品質監査
- 運営報告書
- 受講者反応の詳細記録
- 個別受講者の相談記録
- 教育設計の再設計
- 教材改訂の決定
- 契約形態ごとの報告義務の定義
- セルフチェック結果の保存・集計・評価制度上の取扱い
- 提出後の修正履歴・管理権限等の記録管理仕様

これらは、それぞれ正式に定められた別成果物・運用・品質保証・講師育成・評価制度等の責任とする。


# 7. 講師育成との境界

15は講師養成教材ではない。

15における内省は、

> **今回の講義実施を振り返り、次回の実施へつなげること**

を目的とする。

講師の性格、価値観、感情、過去経験、心理的背景等まで掘り下げることを要求しない。

「より深い内省が講師の成長につながる」等を理由として、講義実施との直接的な関係を超えた自己分析を追加してはならない。

講師本人が自発的に考えることは妨げない。

内省は、次回の実施へつながる必要十分な深さとする。


# 8. 講師育成・評価制度との境界

15自身は、講師に対する点数・ランク・合否・認定等の評価を行わない。

セルフチェック結果の、

- 保存
- 蓄積
- 集計
- 講師育成への活用
- 資格要件への活用
- 評価制度上の取扱い

等は15では定義しない。

これらは、別途定められた講師育成・運用・評価制度の責任とする。

一方、将来的に別制度が15の結果を講師育成・評価資料として利用する可能性を、15側から禁止しない。


# 9. 契約形態・実施形態との境界

15は、請負講師・ライセンス講師等の特定契約形態だけに依存する成果物として設計しない。

セルフチェックそのものは共通の教育品質確認・内省機能を持つ。

一方、

- 誰へ報告するか
- いつまでに報告するか
- 未実施教育を誰が回収するか
- 本部がどこまで管理するか
- ライセンス講師自身がどこまで対応するか

等の契約・運用上の責任は15では新規定義しない。

正式に定められた運用ルールに従う。


# 10. セルフチェック対象の基本情報

15には、セルフチェック対象となる実施を識別できる基本情報を持たせる。

原則として、

- Course・講座
- Session
- 実施日
- 講師

等、どの講義実施についてのセルフチェックであるかを後から判別するために必要な情報を配置する。

ただし、「管理上あると便利」という理由だけで、15のMissionに不要な管理項目を追加してはならない。

基本情報はセルフチェック対象を識別するためのものであり、15を実施報告書・運営記録票へ拡張するためのものではない。


# 11. セルフチェックの基本構造

15は原則として、以下の順序で構成する。

1. 実施識別情報
2. Sectionごとの固有チェック
3. 講義全体に共通する最小限のチェック
4. 「できなかった」事項についての内省
5. 「判断に迷う」事項についての確認・共有
6. 教材・資料へのフィードバック
7. 講義全体の内省
8. 次回実施への接続

Section固有チェックは、13・14等と対応する正式なSection構造・講義進行順に沿って配置する。

制作AIがチェックしやすいという理由で、

- 安全項目
- ワーク項目
- 説明項目
- コミュニケーション項目

等の独自カテゴリへ再編してはならない。


# 12. Sectionごとの固有チェック

Section固有チェックでは、そのSectionについて講師自身が担う最低ラインの実施責任を確認する。

主な対象は、

- 必須教育内容
- 必須実施条件
- 当該Sectionの教育成立に直接関わる実施境界
- 当該Sectionで破ると承認済み教育が変わる禁止事項

等のうち、15で確認責任を持つべきものとする。

各Sectionの項目数を揃える必要はない。

Sourceを追跡した結果、独立した確認責任が存在しないSectionについて、見た目の均等性を理由としてチェック項目を生成してはならない。

逆に、他Sectionより項目数が多いことを理由として必要な確認責任を削除してはならない。


# 13. 講義全体の共通チェック

Section固有チェックの後に、講義全体を横断して確認する必要がある最低ラインのみを、共通チェックとして配置できる。

共通チェックは必要最小限とする。

同じ内容を各Sectionで繰り返し確認する必要がない場合、全体共通として一度確認できる。

ただし、特定Section内で判定すべき責任を、「共通項目だから」という理由で講義全体側へ移動してはならない。


# 14. チェック項目の対象

15に正式なチェック項目として採用するものは、

> **教育品質上の最低ラインを確認するために必要な実施責任**

に限定する。

「確認できると望ましい」
「講師として意識した方がよい」
「安全のため念のため」
「講師の成長に役立つ」
「確認した方が品質が上がる」

等を理由として、新しいチェック項目を追加してはならない。

必要な確認項目を省略して情報量を減らしてはならない一方、品質向上を理由として確認責任を増殖させてもならない。

**チェック項目数を増やすことを品質向上とみなさない。**

固定の項目数上限は設けず、承認済み教育の最低ラインを確認するために必要十分な量とする。


# 15. チェック項目の具体性

チェック項目は、可能な限り講師自身が実施事実として確認できる粒度・表現にする。

「適切に」
「十分に」
「効果的に」
「うまく」

等、講師自身が判定基準を補完しなければならない抽象表現だけで確認させない。

可能な場合は、

- ○○について説明した
- 個人で考える時間を確保した
- 共有を全員必須にしなかった

等、実施事実として判定できる形へ整理する。

ただし、確認可能性を高める目的で、制作AIがSourceに存在しない、

- 必須条件
- 達成水準
- 判断基準
- 実施条件

を新しく生成してはならない。

Source上の一つの責任を複数項目へ整理する場合も、意味・要求水準・必須性を変更してはならない。


# 16. チェック項目の重複禁止

同一の実施事実を、表現や参照元が異なることだけを理由として複数のチェック項目へ重複させない。

一回の判定で確認責任を満たせるものは、意味を損なわない範囲で統合する。

ただし、表面的に類似していても、

- 異なるSection責任
- 異なる必須教育内容
- 異なる必須実施条件
- 独立した実施境界

として別の確認責任を持つものは統合しない。

「重複を減らすこと」を理由として、独立した確認責任を消してはならない。


# 17. 禁止事項の扱い

13・14その他の正式資料に存在する禁止事項を、網羅的に15へ転載しない。

禁止事項のうち、

- 当該Sectionの教育成立に直接関わるもの
- 破ると承認済み教育そのものが変わる重大な境界
- 講義全体として最低ライン確認が必要な重大な越境防止

等は、必要に応じてチェック対象とする。

同じ意味の禁止事項を細分化して複数チェックへ増殖させない。

「正式資料に禁止事項として書かれている」という理由だけで、すべてを15へ再掲してはならない。


# 18. 教材品質と講師実施の分離

15は講師自身の実施責任を確認する成果物であり、教材そのものの制作品質を再検査する成果物ではない。

PPT・受講者配布資料・ワークシート等について、

- 正しい内容が記載されているか
- 必要情報が掲載されているか
- 制作基準どおり作られているか

等を講師へ毎回確認させない。

ただし、

- 指定教材を使用する
- 指定タイミングで提示する
- 指定資料を配布する

等の行為が承認済みSource上で講師の必須実施責任として定められている場合、その使用行為はチェック対象になり得る。

**教材品質の確認と、講師による教材使用の実施確認を混同しない。**


# 19. 判定区分

基本となる判定区分は、

- できた
- できなかった
- 判断に迷う

とする。

正式に条件付き・状況依存として定義された項目についてのみ、

- 該当なし

を使用できる。

講師または制作AIが独自判断で「該当なし」を設定してはならない。


# 20. 「該当なし」の使用条件

「該当なし」は、

1. 承認済みSource上で当該事項が条件付き・状況依存として正式に定義されており、
2. 今回、その実施条件が発生しなかった

場合に限って使用する。

時間不足、失念、準備不足等を理由として「該当なし」を使用してはならない。


# 21. 「できた」の扱い

「できた」は、講師自身が実施事実として最低ラインを満たしたと判定できた状態とする。

「できた」と判定した項目について、

- 具体的に何を話したか
- どのように実施したか
- できたことの証明
- 実施根拠の作文

等を毎回必須記入させない。

「できた」は判定のみで完了してよい。

講師本人が次回も再現したい実施方法等を残したい場合は、講義全体の内省で扱うことができる。


# 22. 「できなかった」の扱い

「できなかった」は、原因に関係なく、

> **正式な最低ラインとして求められた実施事実が成立しなかった**

場合に使用する。

「できなかった」は、講師の力量不足を意味しない。

「できなかった」と判定した項目は、原則としてすべて内省対象とする。

少なくとも、以下を振り返れる構造とする。

1. **なぜ実施できなかったと考えるか**
2. **講師自身の実施によって改善可能な事項である場合、次回どのように実施するか**

「できなかった」項目について、理由の内省を任意扱いにしてはならない。

一方、教材・運営・環境その他、講師自身では解消できない事項について、

> 次回、自分がどう改善するか

を無理に生成させない。

講師自身では解消できない事項が含まれる場合は、本人だけの改善課題として閉じず、正式な共有・フィードバックへつなげる。

原因分類を制作AIが先回りして固定しない。

理由は原則として自由な内省によって扱う。


# 23. 複数の「できなかった」の扱い

「できなかった」項目はすべて内省対象とする。

ただし、複数項目に共通する原因・次回対応がある場合、関連項目をまとめて内省してよい。

同じ原因・同じ内省を項目数分繰り返し記入させる必要はない。

重要なのは、すべての未実施事項が内省対象として扱われることであり、同一文章を複数回記入させることではない。


# 24. 「判断に迷う」の定義

「判断に迷う」は、

> **講師が一時的に迷った状態**

を意味しない。

まず、15から指定された13・14その他の正式資料を確認する。

正式資料を確認した結果、

- 「できた」と判定できる
- 「できなかった」と判定できる

場合は、その判定へ進む。

正式資料を確認してもなお、

> **自分の実施が正式な最低ラインを満たしたか判定できない**

場合に「判断に迷う」とする。

資料を確認することで迷いが解消した場合は、教材側の判断不能事項として扱わない。


# 25. 「判断に迷う」場合の対応

「判断に迷う」場合は、

- どの項目について迷ったか
- どの正式資料を確認したか

を確認できるようにする。

講師自身へ、

- 正解を推測させる
- 新しい判断基準を作らせる
- 自分で改善策を作らせる

ことを要求しない。

正式資料を確認しても判断できない場合は、正式な確認・共有先へつなげる。

**「判断に迷う」は、自己解決のための内省ではなく、正式な判断へ戻すための状態である。**


# 26. 参照性

15は、講師が判定に迷った場合に正式な判断根拠へ戻れる参照性を持たせる。

ただし、すべてのチェック項目へ機械的に大量の参照情報を表示する必要はない。

15単体で実施事実を明確に判定できる項目は、15上の記載だけで完結してよい。

詳細な条件・境界等の確認が必要な項目については、13・14その他の正式参照先へ戻れるようにする。

15に教育意図・教育設計・ゴール・詳細説明等を大量再掲してはならない。

**15は参照先へ戻るための入口を持つが、13・14の代替資料にはならない。**


# 27. 制作時のトレーサビリティ

完成15にすべてのSource情報を表示する必要はない。

一方、制作AI・レビュー・監査上は、各チェック項目について正式な根拠を追跡できなければならない。

制作時には、

> **このチェック項目が、どの承認済み教育設計・上位基準等の正式Sourceから成立しているか**

を確認可能にする。

13・14は、そのチェック責任が実際の進行・実施判断と整合しているかを横断照合する。

完成15では、講師が判断するときに必要な参照先のみ表示する。

**制作・監査側には十分なトレーサビリティを持たせ、講師側には必要十分な参照性を持たせる。**


# 28. 教育設計等の再掲禁止

15には原則として、

- 教育設計本文
- Sectionの教育意図
- 詳細な教育ゴール
- 教育的背景説明
- 講師理解用の長文説明

等を再掲しない。

完成15の中心は、

> **講師自身が最低ラインの実施事実を確認できる情報**

とする。

教育意図・ゴール・判断背景等の詳細確認が必要な場合は、14その他の正式参照先へ戻る。


# 29. 講義全体の内省

Section単位の最低ライン確認とは別に、講義全体を俯瞰する内省を持たせる。

講義全体の内省では、原則として、

- 今回、次回も続けたい・再現したいこと
- 今回、改善したいこと
- 次回の実施で意識したいこと

等、講師自身の実施スタイルを育て、次回へつなげるための必要十分な内省を行えるようにする。

すべての「できた」項目について成功理由を書かせる必要はない。

講師自身が再現したい実施方法を自覚・記録できる余地を持たせる。


# 30. 次回実施への接続

15は、今回の内省を次回の実施へ接続できる構造を持つ。

前回の15に記録された、

- 次回意識したいこと
- 再現したいこと
- 必要な内省

等を、次回実施前に確認できるようにする。

ただし、これを理由として、

- 実施前準備チェック
- 教材確認チェック
- 学習確認
- 目標設定
- 能力開発計画

等を15へ追加してはならない。

**前回15の参照は、内省を次の実践へ接続するためのものであり、15を実施前管理資料へ拡張するためのものではない。**

また、前回の課題が今回改善したかを独立して評価・判定する項目は原則設けない。

成長履歴の評価は、別途定める講師育成・評価制度の責任とする。


# 31. 教材・資料へのフィードバック

15には、講師自身の内省とは別に、教材・資料側へのフィードバック導線を持たせる。

対象には、

- 教材間の不整合・矛盾
- 参照先の誤り
- 参照不能
- 表記・指示の不一致
- 実際に使用して初めて気づいた分かりにくさ
- 誤記等によって実施へ影響する可能性があるもの
- その他、教材・資料について提供元へ共有・確認したい事項

等を含めることができる。

講師は「教材に問題がある」と確定判定する必要はない。

発見した疑義・違和感・不整合等を共有できればよい。

その原因が、

- 教材不備
- 講師側の理解
- 講師養成
- 運用
- 上位設計

のどこにあるかを判断することは、15の責任ではない。


# 32. 教材不具合発見時の境界

講義中に教材・資料間の不整合や疑義へ気づいた場合、15は新しい緊急対応ルールを定義しない。

講師は正式な実施基準・運用ルールに従う。

15から、講師へ教育仕様・教材内容を独自修正する権限を与えてはならない。

実施後は、正式な教材フィードバック導線へつなげる。


# 33. 受講者反応の扱い

15に、受講者反応・発言・質問等を記録するための専用欄を原則設けない。

講師本人が、自身の実施を内省するうえで必要だと判断した場合、自由記述内で内省材料として扱うことは妨げない。

ただし、15から受講者の反応観察・詳細記録を標準業務として要求しない。

受講者反応を講師の実施達成判定や受講者ゴール達成判定そのものへ置き換えない。


# 34. 自由記述欄の制限

自由記述欄は、

- 必要な内省
- 次回実施への接続
- 判断に迷う事項の確認
- 教材・資料等へのフィードバック

に必要な範囲へ限定する。

「講師の成長に役立ちそう」
「振り返りが深まりそう」

等を理由として、

- 一般的な感想
- 今日の気づき
- 感情
- 自己評価
- 今日一番印象に残ったこと
- 自分を褒める欄

等の自由記述を独自追加しない。

**15を講師日誌・振り返りワーク・講師養成教材へ拡張しない。**


# 35. 中立的な設計

15は、講師が実施事実を正直に記録できる中立的な設計とする。

「できた」が望ましい回答、
「できなかった」が失敗、
「判断に迷う」が能力不足

であるかのような評価的・誘導的表現を使用しない。

「できなかった」は次回の実施へつなげるための事実であり、「判断に迷う」は正式資料を確認しても判定できない事項を適切な確認先へ戻すための情報である。

制作AIは、講師へ望ましい回答を選ばせることを目的とした表現・構造を追加してはならない。


# 36. 重要度・点数・合否の禁止

15のチェック項目に、

- 重要度
- 優先度
- 点数
- ★等のランク
- 推奨度

を付与しない。

15の正式なチェック対象として採用された項目は、すべて教育品質上の最低ラインを確認するための確認責任を持つ。

「重要」「推奨」「参考」等の独自階層を制作AIが追加してはならない。

また、講義全体について、

- 点数
- 評価ランク
- 合格／不合格

等の総合判定を行わない。


# 37. セルフチェック中の判定修正

セルフチェック中に正式資料を確認した結果、当初の判定が実施事実と異なることが分かった場合は、実施事実に即した判定へ修正する。

最初に選択した判定を維持することより、実際の実施を正確に振り返ることを優先する。

一方、

- 提出後・保存後の修正可否
- 変更履歴
- 管理権限

等は15では定義せず、別途定める運用・記録管理の責任とする。


# 38. 共有導線

「判断に迷う」事項、教材・資料への疑義、講師自身では解消できない問題等について、講師が正式な共有先・手順へ到達できる導線を持たせる。

ただし、

- 担当者名
- 連絡ツール
- 具体的な共有手順

等を15の制作基準そのもので固定しない。

「共有が必要」とだけ記載して共有先を不明確にすることも、15の中で共有運用そのものを新規定義することもしない。

具体的な共有先・方法は、正式な運用ルールを参照する。


# 39. セルフチェック結果と教育変更の分離

15のセルフチェック結果は、教育設計・教材・実施基準等を自動的に変更する根拠とはしない。

「できなかった」「判断に迷う」が繰り返されたこと、講師の内省、教材への疑義等は、品質改善を検討するための重要なフィードバックとなり得る。

ただし、その結果のみを理由として、講師または制作AIが、

- 必須教育内容を削除・変更する
- 必須実施条件を緩和する
- 教育深度を変更する
- Section責任を移動する
- 教育活動を追加・削除する
- 教材内容を独自修正する

ことはできない。

15は問題を発見・記録・共有するところまでを担う。

変更要否の判断は、正式な品質保証・改訂プロセスへ戻す。


# 40. 制作AIの裁量

制作AIは、承認済みSourceの意味・要求水準・責任を変更しない範囲で、

- 情報整理
- 見出し構造
- チェック項目の表現整理
- 可読性調整
- 重複整理
- 必要な参照表示
- レイアウト
- 自由記述欄の配置

等を自律判断できる。

複数の妥当な制作案が存在する場合、教育仕様変更を伴わない通常の制作判断まで上位判断へ戻す必要はない。


# 41. 制作AIが行ってはならないこと

制作AIは、15制作時に以下を行ってはならない。

- Sourceにない最低ラインを生成する
- Sourceにないチェック項目を追加する
- 「望ましい」を「必須」へ変える
- 判定基準を推測生成する
- 受講者ゴールそのものを講師の自己判定項目へ変換する
- 受講者反応から学習成果達成を推測させる
- 一般論から最低ラインを補完する
- 他Session・他Courseから類似基準を移植する
- Primary Source等から教育意図・実施責任を推測する
- 情報量を揃えるために項目を追加・削除する
- チェック項目数を増やすことを品質向上とみなす
- 同一の実施事実を複数項目へ重複させる
- 禁止事項を網羅転載する
- 教育設計・14等の説明を大量再掲する
- 実施前チェック機能を追加する
- 講師養成機能を追加する
- 評価・採点機能を追加する
- 教材品質監査機能を追加する
- 講師日誌・感想記録機能を追加する


# 42. 判定基準を確定できない場合の停止条件

チェック対象であることは確認できても、その成立条件・最低ラインを承認済みSourceおよび正式参照資料から確定できない場合、制作AIは独自の判定基準を生成してはならない。

まず正式な参照先へ戻る。

それでも確定できない場合は、上位判断へ差し戻す。

以下を根拠として「できた」の基準を補完してはならない。

- 一般論
- 教育上望ましい状態
- 他Sessionの類似例
- 他Courseの類似例
- 制作AI自身の推論

判定可能性を高めるための表現整理はできるが、判定基準そのものを新しく作ることはできない。


# 43. Source間矛盾時の停止条件

承認済み教育設計・上位基準・13・14その他の正式参照資料間で、

- チェック対象
- 成立条件
- 必須性
- 実施条件
- 裁量境界
- Section責任

等に矛盾または両立不能な記載を発見した場合、制作AIは独自に優先順位を決定してはならない。

「より詳しい」
「より新しいと思われる」
「教育的に妥当」
「一般論として自然」

等を理由として、いずれか一方を正とみなして15へ反映してはならない。

矛盾を独自に統合・平均化・解釈して解消することも禁止する。

矛盾を特定したうえで制作を停止し、上位判断へ差し戻す。

正式な判断によって矛盾が解消された後、その確定内容を15へ反映する。


# 44. セルフレビューの基本原則

制作AIは、15完成後にセルフレビューを実施する。

セルフレビューは、

> **余計なものを足していないか**

だけではなく、

> **必要なものを落としていないか**

を両方向から確認する。

完成15からSourceへ戻る確認と、Source側から完成15へ戻る逆照合の双方を行う。

制作AIの裁量範囲内で修正可能な問題を発見した場合は、監査提出前に自己修正し、再確認する。

制作AIの裁量を超える教育判断・矛盾・情報不足等については、独自修正せず上位判断へ戻す。


# 45. Source側からの逆照合

承認済み教育設計・上位基準等に存在する、15で確認責任を持つべき最低ラインが、完成15ですべてチェック対象として拾われているか確認する。

13・14とも横断し、実際の進行・実施判断との整合を確認する。

「簡潔にする」
「重複を減らす」
「チェック疲れを防ぐ」

等を理由として、必要な確認責任を欠落させてはならない。

同時に、15側の各チェック項目について正式な根拠が存在することも確認する。

**「余計なものを足していない」と「必要なものを落としていない」を両方向から検証する。**


# 46. チェック疲れ・形骸化の防止

15は継続的に使用される成果物である。

そのため、必要以上のチェック項目・記述項目によって、

- 内容を読まずにすべて「できた」を選ぶ
- 内省を形式的に記入する
- 毎回同じ回答を機械的に行う
- セルフチェックそのものを避ける

等の形骸化を招かないようにする。

必要な最低ライン確認を削ることで軽量化してはならない。

一方、「確認項目が多いほど品質が高い」という設計にもしてはならない。

**必要な確認責任を漏れなく保持しながら、継続使用できる必要十分な情報量とする。**


# 47. 完成15の総合実用性確認

個々のチェック項目・内省項目・参照関係が正しいことだけで完成としない。

完成した15を、必要な養成・前提知識を満たした新人講師が実際に使用したとき、

- 何を確認するのか理解できる
- 実施事実として「できた／できなかった」を判定できる
- 受講者ゴールそのものを講師が達成判定する構造になっていない
- 必要な場合のみ「該当なし」を正しく使用できる
- 判断に迷った場合、正式な参照先へ戻れる
- 正式資料を確認しても判断できない場合、独自判断せず正式な確認・共有へつなげられる
- 「できなかった」事項について必要な内省ができる
- 講師自身で解消できない問題を本人の力量不足として抱え込まない
- 教材・資料側の疑義や不具合を正式なフィードバックへつなげられる
- 講義全体を振り返り、再現したいこと・改善したいこと・次回意識することを整理できる
- 次回実施前に前回の内省へ戻れる
- 過剰なチェック・記述負荷によって形骸化していない

ことを成果物全体として総合確認する。

各項目が個別には正しくても、実際の講師が迷わず継続使用できず、

> **実施確認 → 内省 → 必要な確認・共有 → 次回への接続**

というMissionを果たせない場合は完成としない。

# 50. 最終原則

講師セルフチェックは、

> **講師を採点するためのものではない。**
>
> **講師に反省させるためのものでもない。**
>
> **受講者の内面を講師が採点するためのものでもない。**
>
> **できなかったことを隠さず、今回の実施を正確に確認し、必要な内省・確認・共有を行い、次の実践へつなげるためのものである。**

最低ラインは共通で守る。

そのうえで講師は、実施経験を重ねながら、自分自身の届け方・再現したい実施・改善したい実施を内省し、自分の講義スタイルを育てていく。

15は、その成長を評価する制度ではなく、

> **一回一回の実施を、次のよりよい実施へ接続するためのセルフチェック**

として機能しなければならない。
